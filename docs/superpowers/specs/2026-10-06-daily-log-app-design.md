# 하루 기록 앱 설계 (MVP)

- 작성일: 2026-10-06
- 상태: 승인됨 (브레인스토밍 결과)

## 1. 배경과 목표

옵시디언을 주 노트앱으로 쓰고 있지만 아이폰에서 동기화가 되지 않아 모바일 기록이 끊긴다. 일반 노트는 옵시디언에 그대로 두고, **하루 기록만 담당하는 별도 앱**을 만든다.

목표는 두 가지다.

1. **할 일을 놓치지 않는다**: 불렛저널(Ryder Carroll)의 rapid logging과 migration을 적용한다.
2. **성장 데이터를 쌓는다**: 기분과 감정 기록을 구조화된 형태로 남겨, 나중에 패턴을 분석할 수 있게 한다.

### 참고한 자료

- 불렛저널: 기호로 빠르게 기록하고, 미완료 항목을 옮길지 버릴지 매번 결정한다(migration).
- 미창친 영상(`youtu.be/l3a9KYmbyvQ`): 상황별 일지 템플릿(완벽주의, 무기력, 감사), 아침 계획과 저녁 마무리 루틴, 기록을 통한 실수 분석과 회복 데이터 축적.
- Daylio: 1분 이내 최소 입력으로 기록이 끊기지 않게 한다.
- Three Good Things(Seligman), 표현적 글쓰기(Pennebaker): 짧고 구조화된 저녁 회고.
- 자기추적 연구: 추적 항목이 많으면 포기한다(tracking fatigue). 항목을 적게 유지한다.

### 범위 밖 (옵시디언 담당)

일반 노트, 지식 정리, 문서 간 링크.

## 2. 기술 선택

- 앱: Expo (React Native), iPhone 우선
- 백엔드: Supabase (Auth, Postgres)
- 로컬 저장: `expo-sqlite`

## 3. 하루 흐름

### 아침: 오늘 화면

- 오늘보다 이전 날짜이면서 `open` 상태인 할 일을 이월 후보로 보여준다.
- 각 항목을 `오늘 하기` / `나중으로` / `버리기` 중 하나로 정리한다.
  - `오늘 하기`: 원래 항목은 `migrated`, 오늘 날짜로 새 항목을 만든다.
  - `나중으로`: 아무것도 바꾸지 않는다(다음에 다시 후보로 뜬다).
  - `버리기`: 원래 항목을 `dropped`로 바꾼다.
- 새 항목을 추가한다. 기호는 `•` 할 일(`task`), `○` 일정(`event`), `–` 메모(`note`)다.

### 낮: 빠른 입력

- 앱을 열면 오늘 화면의 입력창에 바로 포커스가 간다.
- 종류를 탭으로 고르고 한 줄을 입력하면 저장된다.
- 할 일은 탭 한 번으로 `done` 처리하고, 다시 탭하면 `open`으로 돌아간다.

### 저녁: 마무리 (1분 이내)

- 기분을 1~5점으로 탭한다. 비워둘 수 있다.
- 선택 사항으로 템플릿 하나를 골라 답한다. 건너뛸 수 있다.

| template | 상황 | 질문 |
|---|---|---|
| `perfectionism` | 완벽주의가 올라온 날 | 무엇을 완벽하게 하고 싶었나? / "지금 완벽주의 반응이 올라온 것뿐"이라고 보면 무엇이 달라지나? |
| `lethargy` | 무기력했던 날 | 무기력의 원인으로 짐작되는 것은? / 오늘을 회복의 시간으로 본다면 무엇을 채웠나? |
| `gratitude` | 감사한 날 | 오늘 좋았던 일 3가지와 그 이유 |
| `free` | 자유 일지 | 자유롭게 쓰기 |

템플릿 질문은 앱 코드에 상수로 둔다. DB에는 템플릿 종류와 답변만 저장한다.

## 4. 설계 원칙

- **놓친 날에도 부담이 없어야 한다.** 연속 기록(스트릭)은 보여주지 않고, "기록한 날 N일"처럼 줄어들지 않는 누적 수만 표시한다.
- **데이터는 처음부터 구조화한다.** 기분 점수, 템플릿 종류, 할 일 상태를 필드로 저장한다.
- 앱은 기록 도구이며 치료 도구로 설계하거나 표현하지 않는다.

## 5. 하루의 경계

- **새벽 4시**를 하루의 시작으로 본다. 00:00~03:59에 입력한 기록은 전날 날짜로 저장한다.
- 날짜는 기기의 로컬 시간대 기준으로 계산해 `YYYY-MM-DD` 문자열로 저장한다.
- 날짜 계산은 한 함수(`logicalDate(now)`)에서만 하고, 모든 화면과 저장 로직이 이 함수를 쓴다.

## 6. 데이터 모델

모든 테이블에 공통으로 다음 필드가 있다.

- `id uuid`: 기기에서 생성한다(오프라인 생성 가능).
- `user_id uuid`: `auth.users` 참조.
- `updated_at timestamptz`: 충돌 판정용. 기기에서 변경할 때 설정한다.
- `deleted_at timestamptz null`: 삭제 표시(soft delete).

### `items`

| 필드 | 타입 | 설명 |
|---|---|---|
| `date` | `date` | 논리 날짜 |
| `kind` | `text` | `task` / `event` / `note` |
| `text` | `text` | 내용, 비어 있으면 안 됨 |
| `status` | `text null` | `task`만: `open` / `done` / `migrated` / `dropped`. 그 외 종류는 null |
| `migrated_from` | `uuid null` | 이월 전 원래 항목의 id |
| `created_at` | `timestamptz` | |

제약: `kind = 'task'`이면 `status`는 null이 아니고, 아니면 null이다.

### `days`

| 필드 | 타입 | 설명 |
|---|---|---|
| `date` | `date` | 논리 날짜, `(user_id, date)` 유일 |
| `mood` | `smallint null` | 1~5 |

### `reflections`

| 필드 | 타입 | 설명 |
|---|---|---|
| `date` | `date` | 논리 날짜 |
| `template` | `text` | `perfectionism` / `lethargy` / `gratitude` / `free` |
| `answers` | `jsonb` | 질문 키별 답변 |
| `created_at` | `timestamptz` | |

### 보안

- 모든 테이블에 RLS를 켜고, `user_id = auth.uid()`인 행만 조회, 추가, 수정할 수 있게 한다.
- 앱에는 Supabase anon key만 넣는다. service role key는 앱에 넣지 않는다.
- 행을 실제로 삭제하는 권한은 주지 않는다(삭제는 `deleted_at`으로만 한다).

## 7. 동기화 (로컬 우선)

- 모든 읽기와 쓰기는 로컬 SQLite에서 한다. 화면은 네트워크를 기다리지 않는다.
- 쓰기를 할 때마다 같은 트랜잭션에서 변경된 행의 id를 `outbox`(미전송 목록)에 기록한다.
- **push**: 연결되어 있으면 outbox의 행을 Supabase에 upsert하고, 성공한 항목을 outbox에서 지운다. 실패하면 outbox에 남겨 두었다가 재시도한다.
- **pull**: 마지막으로 받은 시점 이후에 `updated_at`이 바뀐 행을 받아 로컬에 반영한다.
- **충돌**: 같은 행이면 `updated_at`이 더 최신인 쪽을 채택한다(last-write-wins). 혼자 쓰는 앱이라 충돌은 드물다.
- **동기화 시점**: 앱 시작, 앱이 포그라운드로 돌아올 때, 로컬 쓰기 직후(짧은 지연 후).
- outbox가 비어 있지 않으면 화면에 "동기화 대기" 표시를 띄운다.
- 데이터는 서버로 전송되기 전까지 기기에 남아 있으므로, 전송에 실패해도 유실되지 않는다.

## 8. 인증

- Supabase Auth 이메일 로그인 한 가지만 지원한다.
- 세션은 기기 보안 저장소에 보관한다.

## 9. 테스트

- `logicalDate`: 03:59와 04:00 경계, 자정 직후, 시간대 처리.
- 이월: `오늘 하기` / `나중으로` / `버리기` 각각의 상태 변화와 `migrated_from` 연결.
- 동기화: outbox 적재, push 실패 후 재시도, last-write-wins 충돌 처리, soft delete 전파.
- RLS: 다른 사용자의 행을 조회하거나 수정할 수 없는지 확인.

## 10. 2차 이후로 미루는 것

- 통계와 대시보드 (기분 추이, 이월 횟수, 템플릿 사용 빈도)
- 푸시 알림 (아침 계획, 저녁 마무리 리마인더)
- 활동 태그 (운동, 수면 등)
- 옵시디언 노트 가져오기와 내보내기
- Mac 또는 웹에서의 입력

## 11. 디자인 확정 사항 (2026-10-07, 목업 피드백 반영)

목업 캔버스: https://claude.ai/artifact/1YTaE6tf1SP4rSBeu8rbMz (서비스명 "나날")

### 11.1 스타일
- 종이 다이어리: 크림 종이 배경 `#F6F0E4`, 먹색 글씨 `#2A2520`, 키 컬러 네이비 `#1E2F4D`, 형광펜 `#F1DE8A`.
- 글꼴: 제목 Gowun Batang(400), 본문 IBM Plex Sans KR(400/500), 손글씨 메모 Nanum Pen Script.
- 전체적으로 가볍게: 굵은 글자 최소화, 선 1px. 화면당 주 버튼 하나만 진한 배경.
- 화면 배경은 모두 민무늬 크림 종이. 저녁 회고 카드만 줄 노트.
- 지난 할 일 포스트잇: 항목을 정리하면 옆으로 밀려나며 사라지고, 마지막 항목을 정리하면 포스트잇이 떼어지듯 사라진다.
- 앱 시작과 온보딩 시작 시 하드커버 표지가 펼쳐지는 모션, 저녁 마무리 "닫기" 시 표지가 덮이는 모션. 동작 줄이기 설정에서는 모션 없음.

### 11.2 기호와 상태 규칙 (스펙 3, 6절 변경)
| 표시 | 의미 | 동작 |
|---|---|---|
| • | 할 일 (`open`) | 기호를 탭하면 진행 중 |
| ◐ (반쯤 찬 동그라미) | 진행 중 (`doing`, 신규) | 탭하면 끝냄 |
| ●✓ (체크가 든 꽉 찬 동그라미) + 취소선 | 끝낸 일 (`done`) | 탭하면 다시 할 일 |
| › | 옮긴 일 (`migrated`) | |
| ○ | 일정 | |
| – | 메모 | |
| 노란 형광펜(글자 밑) | 중요 (`priority`, 신규) | 줄 오른쪽 ⋯ 메뉴에서 칠하고 지움. 하루 3개까지. 메모에는 없음 |
| ⋯ → 지우기 | 지우기 | 줄 오른쪽 ⋯ 메뉴. 확인 창을 띄운 뒤 soft delete |

- `dropped`(놓아준 일) 상태는 없앤다. 버리기는 지우기(×)로 통일한다.
- 오늘 목록 정렬: 진행 중 → 형광펜(중요) → 나머지(입력 순서) → 끝낸 일.
- 줄 앞에는 상태 기호 하나만 둔다(아이콘을 나란히 두지 않는다).
- 입력 줄: 첫 줄은 입력 칸 + 말로 적기 버튼, 아래 줄에 종류 칩(• 할 일 / ○ 일정 / – 메모)과 (i).
- 기호 버튼 옆 (i)를 누르면 기호 설명 팝오버.

### 11.3 지난 할 일 정리 (스펙 3절 변경)
- 버튼: "오늘 하기" / "내일로" / ×(지우기).
- "내일로"는 원래 항목을 `migrated`로 바꾸고 내일 날짜로 새 항목을 만든다(목업의 "나중으로"를 사용자가 "내일로"로 바꿈. 구현 전 확인).

### 11.4 추가 화면
- 온보딩 4단계: 환영 / 기호 소개 / 하루 흐름 / 완료. 진행 점, 건너뛰기, 이전.
- 지난 기록: 달력(날짜별 잉크병 기분, 회고 점)과 회고 모아보기(템플릿 필터). 새 테이블 없이 `days`, `reflections`, `items`를 날짜별로 조회.
- 기분 입력: 1~5를 잉크병에 차오르는 잉크로 표현, 고른 병에 깃펜.

### 11.5 말로 적기 (2차)
- 기기 음성 인식(STT) → 받아쓴 글을 Supabase Edge Function에서 Claude Haiku로 정리(종류, 내용, 날짜) → "이렇게 정리했어요" 확인 후 추가.
- 음성 원본은 저장하지 않는다. 서버 함수에 하루 호출 제한(예: 50회). 오프라인이면 받아쓴 글을 메모로 저장.
- 개발용 빌드 필요(Expo Go 불가).

### 11.6 위젯 (2차, 개발용 빌드 + Swift WidgetKit)
- 잠금화면: 직사각형(다음 할 일 + 완료 버튼), 원형(남은 수, 오늘 기분), 컨트롤 버튼(말로 적기, 한 줄 적기, iOS 18+).
- 홈 화면: 중간(오늘 할 일 3개 + 체크), 작은(기분, 기록한 날), 큰(상태 칩: 밀린 일/할 일/진행 중/한 일, 탭하면 다음 상태).
- 잠금화면 "다음 할 일" 선택 규칙: 진행 중 → 1시간 안에 시작하는 일정 → 형광펜(중요) → 오늘 목록 순서. 밀린 일은 개수로만.
- 데이터: SQLite를 App Group 공유 폴더로 옮겨 앱과 위젯이 같은 DB 사용. 위젯 변경도 outbox에 기록하고 동기화는 앱이 한다.
- 위젯 안 텍스트 입력과 녹음은 iOS에서 불가 → 앱을 해당 화면으로 연다.

### 11.7 데이터 모델 변경 요약
- `items.status`: `open | doing | done | migrated` (`dropped` 제거). 로컬·서버 CHECK와 기존 `dropped` 행 처리(→ soft delete) 마이그레이션 필요.
- `items.priority`: boolean, 기본 false (로컬·서버 컬럼 추가, 동기화 컬럼 목록 추가).

### 11.8 회고 템플릿 (스펙 3절 변경)
- 기본 템플릿: 무기력했던 날(`lethargy`), 감사한 날(`gratitude`), 자유 일지(`free`). "완벽주의가 올라온 날"(`perfectionism`)은 없앤다.
- 사용자가 템플릿을 추가할 수 있다: 이름 + 질문 1~3개(질문 1 필수).
- 데이터: 새 테이블 `templates`(id, name, questions jsonb, created_at, updated_at, deleted_at, 동기화·RLS는 다른 테이블과 같음).
- `reflections.template`의 고정 CHECK를 없애고 기본 키 또는 사용자 템플릿 id를 담는다. 템플릿이 바뀌거나 지워져도 지난 회고가 읽히도록, 회고 저장 시 템플릿 이름과 질문을 `reflections`에 함께 저장한다(스냅샷).
- 기존 `perfectionism` 회고는 그대로 보여준다(스냅샷이 없으면 기본 이름 사용).
